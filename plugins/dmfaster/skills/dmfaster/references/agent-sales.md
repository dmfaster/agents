# Appointment-setting foundation (Agent 2.0)

Inspect `connection_status` first. Confirm workspace identity and `isSandbox`; readiness separately reports provider connection health and granted scopes. A scope is not a connected provider. Follow `setupUrl` for recovery; do not try browser cookies or private credentials.

For development or a requested dry run, create a sandbox with `workspace_sandbox_create`, reconnect selecting that workspace, and verify `workspace.isSandbox:true` before `sandbox_seed`. The `appointment_setter_v1` preset supplies 50 synthetic targets, mixed-intent conversations and meetings. `sandbox_inbound_simulate` and `sandbox_clock_advance` require fresh versions where applicable and durable idempotency keys. `sandbox_provider_update` exercises disconnection; sandbox providers record fake receipts and cannot acquire real connections. Do not switch to a live workspace to make a sandbox operation succeed.

Read `conversations_changes` once without a cursor to establish a watermark; keep and advance the returned cursor. Use exact `intent`, `interest`, `channel`, `meetingStatus`, `followupDue` and `updatedAfter` filters with `conversations_list`. `filteredTotal` is the exact filtered count; `scopeStats` describes the selected campaign/channel/mailbox/search scope before status and interest filters. A reaction or system marker is not a human reply. Human/agent intent overrides persist across model classification.

Subscribe to classified human messages, opted-out contacts, meeting outcomes and sender health using `webhooks_create` or hosted MCP Events. Use `events_list` to recover after a disconnection. Save the secret privately; deduplicate by event `id`, preserve per-workspace sequence, and verify DMF-Signature against the raw request body with a five-minute timestamp tolerance. The same event can have multiple delivery IDs after replay. Inspect a resource again before mutating from an old event.

An opt-out must stop outreach across channels. Use `suppressions_add` for an explicitly requested removal; removal of a suppression requires a reason and owner permission. Never use a second channel to bypass a suppression. Existing historical opt-outs may require a separately approved repair; absence from the ledger is not permission to ignore the prospect's request.

Use `call_outcome_set` to record held/no-show/rescheduled/cancelled and won/lost/follow-up outcomes from actual evidence. Do not infer attendance from a calendar timestamp. `awaiting_outcome` means evidence is missing. `meeting_link` and `meeting_unlink` require current versions. `pipeline_reconcile` is read-only for live workspaces; historical apply needs a separate owner-reviewed maintenance task. Closed won/lost metadata preserves the existing closed stage.

Keep each key stable for retries of the same intent; inspect the durable action/receipt after ambiguous transport failures. Change the key for a new intent. Agent 2.1 permits automatic template replies only under the current owner-approved policy and approved template version. Free text needs exact owner approval. Discover tools and granted scopes before use.

## Reply policy and due work (2.1)

Request only the needed `policy:write` and inbox/calendar scopes. Create template proposals with `reply_templates_create`, then let the owner approve each version at the returned browser URL. Propose a disabled starter policy: Europe/Helsinki Monday–Friday 08:00–18:00, 25/day and 2/thread/day, confidence ≥0.8, only explicitly selected templates/channels/intents, no free text and no opt-outs. Enabling or changing it needs the focused owner browser approval. `reply_policy_get` reports the effective version. Never self-approve through a browser or treat a pending proposal as active.

`conversation_reply` accepts templateId and closed-set variables. Read policyDecision: auto_allowed means authorized; inspect the returned action to establish delivery. approval_required creates a draft; the owner can edit, approve or reject it in Agent sessions on desktop/mobile. Keep the original key through retries. Only set ownerApproved:true for free text that the user actually approved verbatim in this conversation. Never infer it from general access.

Use `conversation_followup_set` with the inspected updatedAt, due time, type/note and optional approved autoSend template. An inbound human message cancels it. `followups_due` is pending work, so already dispatched/cancelled items are excluded; nextAction fields remain visible on conversation reads. Re-check current versions after events. Live `campaign_followups_configure` supports future_only and dryRun; contacted_no_reply application is sandbox-only pending separate owner-reviewed maintenance.

## Booking and measurement

Use `calendar_availability` suggestedSlots for Finnish/English proposals. `calendar_booking_link_create` needs the conversation version, one-use expiry, bounded window and explicitly approved invitation settings. Its secret URL is for the intended prospect; never log it. Creating the link does not send it. Teams requires a supplied Teams URL; use custom_url when appropriate. calendarId selects an owned calendar, default primary. Reschedule/cancel require exact meeting versions and durable keys. If a calendar mutation is pending, retry that exact operation; do not issue a second conflicting command.

`campaign_variants_configure` changes future approved copy only. Choose the channel, stable variant IDs, weights and minimum sample. Manual promotion is the default recommendation; bayesian_95 is optional and conservative. `copy_performance` reports coverage and intervals without guessing historical text. Use `analytics_summary` range/from/to/groupBy for scoreboards; unknown historical actors stay unknown. `canonicalMetrics` is the consistent comparison field across analytics, campaign and pipeline. Legacy counts use older definitions. Bulk updates report each item's conflict independently. Historical merge, attribution, opt-out and meeting repairs require a separate reviewed dry run and explicit approval.
